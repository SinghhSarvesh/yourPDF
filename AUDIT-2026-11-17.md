## Measurements and their limits

Comparable before/after static import analysis is reproducible with `python audit/import-sizes.py`; baseline content is read directly from Git. This is the dependency closure of `pdf-app.js`, not all page resources.

| Metric | Baseline | Draft |
|---|---:|---:|
| Initial PDF UI static JavaScript, uncompressed bytes | 563,291 | 35,150 |
| Reduction | — | 528,141 bytes (93.8%) |
| PDF library required for actual processing | Yes | Yes, when needed |
| Mobile/desktop LCP, INP, CLS, long tasks | Not obtained | Not obtained |

Do not interpret the byte reduction as a 93.8% speed improvement. Network compression, cache state, parsing and device CPU affect actual loading. The library still loads in the processing worker; sample generation can also import it on the main thread.

Earlier HTTP-only baseline: three sequential urllib fetches per URL, four concurrent URL groups, no device/CPU emulation. Median full-response times in milliseconds were: home 7,208.09; merge 6,946.58; photo 7,030.92; signature 7,299.28; PDF-to-JPG 7,011.61; application guide 7,111.20; download help 7,253.45. These include execution-environment network latency and are **not page render times**. Original raw files were lost during workspace recovery. `audit/http-baseline.py` provides a repeatable HTTP probe; any recovered rerun results are stored separately and must not be presented as an after-deployment comparison.

PageSpeed API returned HTTP 429 (quota); the browser's read-only evaluation environment did not expose Performance APIs. No Lighthouse score, mobile or desktop rendering median, layout-shift trace, long-task trace, heap profile or real-user Core Web Vitals was obtained. No fresh Search Console/CrUX/analytics data was available. Prior conversation traffic figures are historical and were not used as current evidence. There is no measured production before/after speed claim.

## AdSense assessment

The site already offers functioning tools and original worked workflows. Privacy, About, Contact, Help and Download Help are present; a contact email is published, though mailbox delivery was not tested. The privacy page explicitly distinguishes local document handling from Netlify page/asset logs and says advertising is inactive. Application source contains no active ad or analytics integration; existing verification configuration is preserved.

The same-origin CSP restricts scripts/connect/frame destinations and currently does not permit a normal Google ad integration. That is consistent with ads being inactive. Do not weaken the CSP speculatively. If advertising is later authorized, review exact provider requirements, consent obligations, truthful homepage/privacy copy and narrowly scoped CSP changes together.

This audit cannot establish Google's internal reason for “low value content,” account eligibility, approval or earnings. Faster code and working navigation do not guarantee approval. Do not check “I have fixed the issues” solely because these technical tests pass. Review the completed user experience and content with the remaining device tests before another submission.
