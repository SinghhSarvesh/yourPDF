# yourPDF launch checklist

## What exists now

Twelve homepage tools (11 PDF operations and a link to the existing image tool), with searchable categories, per-tool pages, source selection, sample documents, previews, real transformations, download states and result chaining. Static documentation, sitemap, canonical URLs and privacy content are included. Heavy libraries are self-hosted. No backend, account, payment, ads or analytics.

The name is provisional and already has a direct web conflict. Do not buy a domain or promote under this name until a distinct final brand is selected.

## Mandatory browser checks before public promotion

- [ ] Open homepage at 360/390px and desktop widths; test search and every category.
- [ ] Try the generated sample in every tool; verify picker, settings, progress, result and reset.
- [ ] Merge two files, reorder and remove files; verify page order in another PDF reader.
- [ ] Split individual pages; extract ZIP and inspect all outputs.
- [ ] Extract ranges; remove pages; reject an empty selection and removing all pages.
- [ ] Organize: move first/last pages, exclude a page and verify output ordering.
- [ ] Rotate selected pages; inspect existing rotated/landscape PDFs.
- [ ] Number and watermark pages with bottom-edge content and unusual dimensions.
- [ ] Optimize an already small PDF; ensure it reports unchanged rather than false savings.
- [ ] JPG export: raster fonts, embedded images, CJK fonts and multiple pages; inspect ZIP and readability.
- [ ] Images to PDF: portrait, landscape, transparent PNG, WebP, EXIF orientations and oversized images.
- [ ] Continue result into another tool; original result and selected tool must match.
- [ ] Cancel a long task; old result must not reappear.
- [ ] Damaged, encrypted, 151-page and >30 MiB files must show understandable errors.
- [ ] Download on Android Chrome, iOS Safari, desktop Edge/Chrome/Firefox.
- [ ] Test keyboard order, controls, status announcements and focus with a screen reader.
- [ ] Inspect actual output in at least two independent PDF readers.
- [ ] Inspect DevTools Network; ensure filenames/content/previews do not leave the browser. Audit hosting-added code separately.
- [ ] Verify actual response CSP and MIME types for `.mjs`, fonts and WASM.
- [ ] Review library security/maintenance and collect no personal test fixtures.

## Scope still missing

OCR, Office conversion, advanced PDF compression, encryption/decryption, digital signatures, redaction and full text editing. Evaluate each with a reliable engine, licensing, operating costs and fidelity tests before adding a tool card. Do not substitute superficial output for these features.

## Owner decisions and accounts

1. Select a distinct final brand and domain after checks.
2. Provide a public support address through normal project configuration; never share passwords.
3. Choose independently controlled hosting after verifying current commercial terms/pricing; no paid services have been activated here.
4. Create/connect the owner's GitHub repository if desired.
5. Confirm device QA, then open public access as a deliberate launch step.
6. After domain connection: verify HTTPS and apex/www redirects; regenerate canonicals and sitemap; verify Search Console via DNS and submit sitemap. Indexing is not guaranteed.

## Differentiation to validate with real tasks

Hypotheses: clearer page selection reduces mistakes; local execution removes upload waiting for typical small files; result chaining reduces repeated selection; visible size limits reduce surprise. Compare task completion, output fidelity, time and user confusion against alternatives. Do not claim superiority without measurements. Existing competitors also offer some of these benefits.

## Analytics and monetization later

No analytics, error telemetry or ads now. If added, send only coarse tool/error codes; exclude filenames, bytes, document text, previews and DOM/session replay. Review consent and provider policies. Keep ads away from file controls with reserved layout space. Check the ad platform's current requirements before applying; approval is not guaranteed.

Revenue scenarios only: page views / 1,000 × assumed RPM. For example, 100,000 views × ₹100 RPM / 1,000 = ₹10,000 revenue before costs/taxes. This is not a traffic, RPM or earnings forecast.

## Maintenance and rollback

Before every release: automated tests, representative real browser tasks, link checks and output review. Monthly: vendored dependency releases/security reports, browser compatibility, infrastructure costs and privacy policy consistency. Keep the previous successful saved Site version. For rollback, redeploy it or revert the bad source commit and re-publish after checks.
